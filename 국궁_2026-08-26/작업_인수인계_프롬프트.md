## 국궁 기획서 (사용자가 준 원문 요지)

### 기본공격 — 무조건 차징형

- **0~50%** : 나가다가 땅에 쳐박힌다. 사거리가 짧다.
- **51~100%** : 사거리 준수, 일반 화살처럼 포물선.
- **100% 에서 3초 더 차징** → **블로우 애로우**. 바람의 꼬리 이펙트와 함께 초고속으로 날아간다.
  벽에 박히면 파편과 함께 작은 광역 충격파.
- **블로우 애로우 상태에서 2초 더 차징하면 실패.** 전용 애니메이션이 나오고 화살은 안 나가며 처음부터 다시.

특이사항
- **100% ~ 블로우 애로우 구간에는 약하지만 빠르고 반복적인 카메라 떨림**이 있어야 한다 (시위를 너무 당겨서 떨리는 느낌).
- 블로우 애로우의 파편 이펙트는 **와키자시 궁극기 "용의 이빨"의 파편을 인용**.
- 바람의 꼬리 모양은 **선풍기 날 세 개에 각각 끈을 달았을 때 생기는 모양**.

### 특수공격 — 주몽의 가호 (쿨 15초)

아바타에 초록 트레일. **5초간 이속 증가 + 2단 점프 + 슬라이딩** 부여.
슬라이딩 버튼은 기존 특수공격 버튼이 5초 동안 바뀌는 형태. 5초가 끝난 뒤부터 15초 쿨이 돈다.

### 궁극기 — 파멸의 빛 (쿨 300초)

발로란트 소바 궁극기와 같은 로직·이펙트. **단 한 발만 발사.** 엄폐물을 통과한다.
발사 직전 **약 1초 동안 궁극기 범위를 알려주는 트레일이 서버의 모든 유저에게 보여야 한다.**

### 애니메이션 계획

사용자가 만들기로 한 것 : 블로우 애로우 실패 시 재장전 / 일반 재장전 / 방어 / 궁극기.

내가 추가로 필요하다고 짚은 것 :
- **블로우 애로우 전용 발사** (평타와 같은 모션이면 힘이 안 실린다)
- **주몽의 가호 발동** (목록에 아예 없었다)
- **방어는 1개가 아니라 2개** — 코드가 `BlockIn` / `BlockOut` 두 클립을 쓴다
- 3인칭 아바타용 : 활 쏘기 / 가호 / 궁극기 (ODA 19본 리그, 에셋 업로드 파이프라인)
- 대기 자세는 안 만들어도 된다 (기본 포즈가 대신한다)
- **차징 떨림은 애니메이션으로 만들지 마라** — 차징 시간이 가변이라 클립으로 길이를 못 맞춘다. 코드로 넣어야 한다.

## 내가 이번에 크게 데인 것 (같은 실수 반복 금지)

**1. MCP 쓰기 도구가 편집을 덮어쓴다.**
`studio_add_script` / `studio_update_part` 는 레벨을 자기 사본으로 다시 저장한다.
`.ovdrjm` 의 Source 를 고친 뒤에 이걸 부르면 **그 편집이 조용히 사라진다.**
이번에 이걸 어겨 패치 두 벌을 날렸고, 사용자는 "고쳤다는데 하나도 안 됐다"는 상태로 한참을 봤다.
→ **쓰기 먼저, Source 편집 나중. 편집 후엔 즉시 `studio_apply` + `studio_save`.**

**2. 지역변수 한도 200.**
`ViewmodelController` 는 최상위 `local` 이 정확히 한도에 붙어 있다.
하나만 늘려도 **에러 한 줄 없이** 스크립트 전체가 로드에 실패하고 뷰모델이 통째로 사라진다.
→ 새 상태·함수는 전부 `MELEE` 테이블에 매달아라.

**3. 재지 않고 추측하지 마라.**
활시위를 두 번 실패한 원인은 방식이 아니라, 파츠의 로컬 축을 시위 방향이라고 **추측**한 것이었다.
메시에 회전이 구워져 있어서 실제로는 20도 어긋나 있었다.
비슷하게, 와키자시가 화면 오른쪽으로 쳐박힌 원인도 하루를 헤맨 끝에 **PIVOT 을 실측하니** 바로 나왔다.
→ 눈에 보이는 문제는 먼저 **숫자로 재라.**

**4. 한 번에 여러 개 바꾸지 마라.**
여러 변경을 묶어 넣었다가 회귀의 원인을 못 찾아 하루를 날렸다.
→ 하나 바꾸고 Play 로 확인, 그 다음 하나.

**5. `PIVOT` 은 절대 좌표다.**
모델을 다시 임포트하거나 옮기면 그 즉시 무효다. 양팔 파츠 CFrame 의 중점으로 다시 재라.
