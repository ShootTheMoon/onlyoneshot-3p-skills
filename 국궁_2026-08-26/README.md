## 지금 동작하는 것

**뷰모델 전환** — 로비 LOADOUT 에서 KOREA 를 고르면 `Gukgung_Viewmodel_Merged` 로 갈아끼워진다.

**나라별 클립 분리** — `ViewmodelConfig.CHARACTERS.korea.CLIPS` 표에 있는 클립만 재생된다.
표에 없는 이름은 "이 나라엔 없는 동작"으로 `nil` 이 돌아간다.

> 이 표가 없으면 와키자시 공격/막기 클립이 국궁 팔을 그대로 몰고 간다.
> 팔 파츠 이름(`Right_Arm_Mesh` / `Left_Arm_Mesh`)이 나라끼리 똑같아서 이름만으로는 안 걸러진다.

```lua
CLIPS = {
    Intro   = "GukgungIntro",
    Attack1 = "GukgungFire",   -- 시위를 놓는 순간
    BowDraw = "GukgungDraw",   -- 누르고 있는 동안 (게이지로 스크럽)
}
```

**차징 공격** — 기본공격 버튼이 유지형이다.
누르면(`InputBegan`) 차징 시작, 떼면(`InputEnded`) 발사.
`CHARGE_TIME = 1.2` 초에 100%. 이 줄을 지우면 예전처럼 눌렀다 떼면 한 방이 된다.

> `Activated` 는 뗄 때 한 번만 오는 신호라 누르고 있는 시간을 알 수 없다. 그래서 누름/뗌을 따로 받는다.
> 일본(차징 아님)은 검증된 `Activated` 경로를 그대로 쓴다 — 새 경로가 안 먹어도 와키자시는 안 깨지게 갈라놨다.
> 버튼 밖에서 떼는 경우를 대비해 전역 `InputEnded` 로 한 번 더 받는다. 안 그러면 영원히 당긴 채로 굳는다.

**당기기 애니메이션** — `GukgungDraw` 를 **시간이 아니라 차징 게이지로** 스크럽한다.
37% 에서 떼면 시위가 37% 만 당겨진 그림이 나온다. 이게 차징의 핵심.

**화살 발사체** — 떼면 실제 파츠가 날아간다. 중력을 받고 포물선을 그리며, 벽에 박히면 3초 뒤 사라진다.
서버(`RyunochiServer`, phase `bow_shot`)를 거쳐 **모든 유저에게 보인다**. 초기값만 보내고 각자 계산한다.
`MELEE.castSolid` 를 쓴다 — 그냥 Raycast 를 쓰면 `CanCollide=0` 인 풀잎에 전부 막힌다.

**색** — 코드가 파츠 **이름**으로 칠한다 (`applyAppearance` → `COLORS[part.Name]`).
FBX 를 다시 넣어도 이름만 같으면 색은 유지된다. 원본 모델 파츠에도 같은 색을 직접 칠해뒀다.

## 아직 안 된 것

- **활시위가 안 휜다.** 아래 "왜 안 되는가" 참고. 관련 코드는 전부 걷어낸 상태다.
- **화살에 명중 판정이 없다.** 순수 시각이다.
- **떼는 순간 와키자시용 근접 판정이 잘못 나간다.** `onAttackPressed` 가 근접 데미지 경로를 그대로 탄다. 화살 명중 판정을 붙일 때 같이 끊어야 한다.
- **블로우 애로우** (100%에서 3초 추가 차징, 카메라 떨림, 실패 시 되돌리기) — `_G.BowCharge` 가 이미 나가고 있어서 붙이기만 하면 된다.
- **주몽의 가호 / 궁극기(파멸의 빛)** — 로직도 애니메이션도 없다.
- **3인칭이 전부 와키자시다.** `AvatarAnimServer.ATTACK_BY_INDEX` 가 무기 구분 없이 `wakizashiattack` 을 재생한다. 남들 눈엔 활을 들고 칼을 휘두른다. ODA 19본 리그로 따로 만들어 에셋 업로드해야 한다.
- **막기/재장전 클립 없음.**
- 팔은 28정점 자리표시용이다.

## 왜 활시위가 안 휘는가

클립이 파츠마다 저장하는 건 **위치**와 **회전** 둘뿐이다. 옮기고 돌릴 수는 있어도 **모양은 못 바꾼다.**

블렌더에서 시위의 V자는 Hook 모디파이어가 **메시의 정점을 옮겨서** 만든 것이다.
직선을 V자로 만드는 "위치+회전" 조합은 존재하지 않으므로 저장할 것이 없다.

> 증거 : 클립을 뽑으면 `Gukgung_String` 숫자가 `Gukgung_Bow` 와 한 자리도 안 틀리고 똑같다.
> 시위 오브젝트 자체는 활에 붙어 안 움직이고 정점만 움직이기 때문이다.

**방법은 둘.**

1. **블렌더에서 시위를 두 개로 자른다.** 각 반쪽이 온전한 오브젝트가 되면 활 끝을 축으로 도는 것뿐이라 그대로 넘어온다.
   다만 당기면 반쪽이 **52.77cm → 60.48cm (+15%)** 로 늘어나야 하는데 클립에 크기 채널이 없다.
   대기 자세 길이로 맞추면 최대 당김에서 7.7cm 모자라고, 최대 당김에 맞추면 대기 자세에서 7.7cm 튀어나온다.

2. **코드로 그린다.** 두 번 시도해 두 번 실패했다. 실패 원인은 방식이 아니라 **치수를 재지 않고 파츠의 로컬 축을 시위 방향으로 추측한 것**이었다.
   메시에 회전이 구워진 채로 임포트돼서 로컬 축이 시위 방향과 약 20도 어긋나 있다.
   (시위 `Size` 가 `(99.282, 36.282, 5.505)` 인 이유 — 길이 105.534 짜리 실이 20도 기울어 있어서 bbox 가 저렇게 나온다.)

   **다시 한다면 이 실측값에서 시작할 것** (블렌더 프레임 10 기준, 파츠 로컬 cm) :

   ```
   TIP_A = (-49.576,  17.934,   2.247)
   TIP_B = ( 49.629, -17.731,  -2.630)
   NOCK  = ( -3.450,  -5.401, -41.933)   -- 화살 파츠 기준. 화살이 당겨지면 저절로 따라온다
   THICK = 1.1
   ```

   검산 : `TIP_A ~ TIP_B` 거리 = **105.534cm** = 실제 시위 길이.  넉 끝 ~ 시위 중점 = **0.731cm**.
   ★ 모델을 다시 임포트하면 이 값도 다시 재야 한다.

## 애니메이션 클립 규격

전부 **블렌더 프레임 10 = 기준(rest) 자세** 로 뽑혀 있다. 인트로만 프레임 60 기준이다.

| 클립 | 블렌더 프레임 | 길이 | 재생 방식 |
|---|---|---|---|
| `GukgungIntro` | 10~60 | 2.083초 | 시간 (`INTRO_SPEED = 0.8`) |
| `GukgungDraw` | 10~34 | 1.0초 | **차징 게이지** |
| `GukgungFire` | 40~43 | 0.125초 | 시간 |
| `GukgungAttack` | 10~43 | 1.375초 | 안 씀 (차징 전 임시본) |

- 좌표 변환 : 배율 100, `R = (x,y,z) -> (-x, z, y)`, `posScale = 240`
- 회전 중심 P (프레임 10) : `(0.139709, 0.222558, -0.124010)` — 양팔 bbox 중점
- 행 구조 : `{시간, [px,py,pz,qw,qx,qy,qz] × 5파츠}` = 숫자 36개
- 파츠 순서 : `Right_Arm_Mesh, Left_Arm_Mesh, Gukgung_Bow, Gukgung_String, Arrow_Gukgung`
- 첫 행이 `0,0,0,1,0,0,0` 이면 기준 프레임이 맞다는 뜻

**발사 클립을 40 부터 뽑는 이유** : 블렌더에서 화살을 숨긴 프레임이 40 이다.
39 부터 뽑으면 첫 프레임에 화살이 65cm 앞 허공에 한 번 번쩍인다.

## 반드시 지킬 것 (여기서 크게 데였다)

**`PIVOT` 은 절대 좌표다.** 모델을 다시 임포트하거나 레벨에서 옮기면 그 즉시 무효가 된다.
양팔 파츠 CFrame 의 중점으로 다시 재라. 2026-08-26 재임포트 때 `(-250, 0, +160)` 만큼 밀렸다.

```
korea PIVOT = { -790.620941, 18.364028, -878.147003 }
japan PIVOT = {  852.228790, 73.029171, 4609.211182 }
```

**`ViewmodelController` 는 최상위 지역변수 한도(200)에 붙어 있다.**
`local` 을 하나만 늘려도 **에러 한 줄 없이** 스크립트 전체가 로드에 실패하고 뷰모델이 통째로 사라진다.
새 상태와 함수는 전부 `MELEE` 테이블에 매달았다 (`MELEE.charging`, `MELEE.bowShoot`, `MELEE.ARROW` …).

**MCP 쓰기 도구를 Source 편집 뒤에 부르지 마라.**
`studio_add_script` / `studio_update_part` 는 레벨을 자기 사본으로 다시 저장하면서 `.ovdrjm` 의 편집을 덮어쓴다.
이번 세션에서 이걸 어겨 패치 두 벌을 날렸다. **쓰기 먼저, 편집 나중.**

**레벨 JSON 을 통째로 재직렬화하지 마라.** 14MB 안의 float 정밀도가 바뀌면 레벨 전체가 흔들린다.
`Patches/ovdr.py` 는 `"Source"` 문자열 구간만 잘라 바꾼다.

**블렌더에서 Ctrl+Z 는 MCP 로 한 작업까지 되돌린다.**

```bash
python p21_reset.py      # .ovdrjm 의 Source 를 고친다
# 그 다음 studio_apply -> studio_save 로 라이브 씬에 반영
```

| `readparts.py` | 레벨 파일에서 파츠 Size/CFrame 실측 |
| `p12_clips.py` | 나라별 클립 분리 |
| `p16_charge.py` | 유지형 버튼 + 차징 |
| `p17_string.py` | (시위 코드 — 지금은 걷어냄) + 발사 클립 40프레임 |
| `p18_arrow.py` | 화살 발사체 + 서버 릴레이 |
